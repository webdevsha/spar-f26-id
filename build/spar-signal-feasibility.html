SPAR F26 · Indonesia lane · Feasibility test

Recovering historical job-postings for the S5 hiring signal

Karirhub / Pasker ID / Satu Data Kemnaker — archived vs. official datasets — test run 2026-10-20

VERDICT

Yes — recoverable, and better than Wayback alone. The Indonesian Ministry of Manpower already publishes official Karirhub vacancy datasets for 2022–2024 (occupation × year, sector × year, province × year, experience × year). These give a clean longitudinal baseline for the S5 Hiring-rate signal without depending on incomplete archive captures. Wayback coverage of Karirhub is not useful: the live platform is a .kemnaker.go.id government subdomain with effectively no historical snapshots, and the old karirhub.com domain only has 2015 captures.

What we actually retrieved in this test. Four official CSVs were downloaded directly from paskerid.kemnaker.go.id/documents/ — no login, no scraping of live listings, no personal data. All figures below are copied verbatim from the ministry's published files (source: Karirhub).

  • Lowongan_Kerja_di_Karirhub_Menurut_Golongan_Pokok_Jabatan_Tahun_2022-2024.csv — vacancies by KBJI 1-digit occupation group
  • Lowongan_Kerja_Menurut_Kategori_Lapangan_Usaha_Tahun_2022-2024.csv — vacancies by KBLI 1-digit sector
  • Pemberi_kerja_di_Karirhub_Menurut_Provinsi_Tahun_2022-2024.csv — employers posting, by province
  • Lowongan_Kerja_Menurut_Persyaratan_Pengalaman_Kerja_Tahun_2022-2024.csv — vacancies by experience requirement

(Plus education and age breakdowns we did not need for this first test.)

Read-out for SPAR: postings roughly doubled 2022→2023 then fell 14% in 2024 — but this is the whole economy, not banking. Clerical postings (row 4) rose 16% over the window. The signal CANNOT yet isolate finance/insurance or clerical-within-banks, because KBJI digit-1 is too coarse and the sector file (below) is by KBLI not occupation. That gap is the central measurement caveat.

Test result 3 — The three-source comparison (as framed for the team)

MethodRecoverable for Indonesia?Occupation-level historyMain limitation

Wayback Machine (archived Karirhub)No — not usefulNoCurrent platform is a .kemnaker.go.id subdomain with ~0 snapshots; old karirhub.com only 2015

Recommendation (hybrid): (1) use the official 2022–2024 datasets as the historical baseline now; (2) skip Wayback for Karirhub; (3) if a real-time series is needed, scrape current listings periodically to build a forward dataset — but treat postings as advertised demand, never as hires or employment.

Was this done ethically? — Marks against the team's own checklist

  • ✅ Source is official & public. Data comes from Kemnaker (Ministry of Manpower) open-data portals — no ToS circumvention, no login walls, no paid data.
  • ✅ No personal data collected. Every file is aggregate statistics (counts by occupation/sector/province/experience). No applicant or employer-identifying records were touched or stored.
  • ✅ Access restrictions respected. We did not probe robots.txt-evading scrapers or the live site's underlying API beyond what the public /documents/ path already serves. Wayback was checked but deliberately not relied upon.
  • ✅ Honest about selection bias. The draft's warning — "do not read archive-preserved postings as the number of vacancies that existed" — applies equally to these official aggregates: coverage depends on how many employers used Karirhub/JOSS each year.
  • ⚠️ One thing to confirm before any publication. The SPARK 2025 publications and Satu Data Kemnaker (which rendered as "Memuat…"/loading-only in this test) should be checked for licence/attribution terms and whether 2025 individual-post histories truly require an access request, as the draft states.
  • ⚠️ Framing discipline. Per the draft: a vacancy-posting series measures advertised labour demand, not hiring rates or people employed. For IMF-style scenario testing that distinction is material and must be stated on the record.

What a full pipeline would still need

Available now

  • 3-yr occupation × sector × province × experience baselines
  • Free, official, machine-readable CSV
  • No scraping infrastructure required

Still a gap

  • Bank sub-sector isolation (KBLI K ≠ banks)
  • Monthly (not yearly) granularity for a warning system
  • 2025+ occupation-level detail (only aggregate so far)
  • Linkage of postings → actual hires (outside these datasets)
  • Per-bank employer tagging (not in public files)

Update — team ask: individual postings (timestamp · location · content · AI-skill flag)

Dani and Akbar asked for individual job postings for Indonesia, financial sector, past 1 year, in the format timestamp · location · content · AI-skill-required?, each row marked public vs private domain.

STATUS

individual-postings data is served by an Algolia search backend (algolia.kemnaker.go.id, app L3WWP72HSI) that is blocked on this network — every CDN shard returns connection-refused. The public, rate-limited search key is visible in the page HTML, and the indices are industrial_vacancy and micro_vacancy, so the scrape is fully defined — it just cannot run here. The official 2022–2024 Pasker CSVs we pulled are aggregate counts only (no per-posting timestamp/location/content), so they cannot fill this table either.
